## 3. Defects found (open)
**D6 (frontend, medium) Native windows narrower than about 560 css px show a page scrollbar and a wrapped status bar.** Repro (5/5, debug and release): pop out a poll or open any native window, narrow it to an outer width of 700 physical px or less at 125 % (inner 546 css px). The bottom status text ("Last OK … · Round trip … · Resp … · Timeouts …") wraps from 18.8 to 37.5 px and the "ESEfact v0.1.0" label wraps from 16 to 32 px; the document becomes 5 px taller than the window (336 vs 331) so a 15 px classic vertical scrollbar appears. Consequences: PollView is 15 px narrower than the client (offsetWidth 451 at the true minimum window, client 466 css px; 466 is only reached at client 481); at the minimum 600 x 400 the toolbar wraps to three rows and the grid shows only three rows. Evidence: `e2e/test-results/evidence/d6-native-min-width-normal.png`; test `INT-EXTRA native window layout at narrow widths` (`16-native-setup.spec.ts`) prints the sweep (gutter 0 up to inner 562 and 15 from inner 546 down). CHK2-F13's "no clipped control" still holds: an extra finding, not a CHK failure.
**D7 (backend or frontend, medium) "Show traffic for this poll" from a native window does not raise or restore W1.** Repro (5/5): pop out P2, minimize W1, then in the native window press `⋯` > "Show traffic for this poll". W1's traffic panel expands with the filter "Poll 2" (checked) but W1 stays minimized and not foreground; with W1 merely behind the native window it also stays behind. CHK2-K5 and K8 (b) require W1 to come to the front, restored if minimized. `mm_show_traffic` (`commands/modbus_master.rs`) only sends the event to the session; nothing focuses W1. The sub-window variant works.
**D8 (frontend, medium for the owner) Keyboard shortcuts are dead while a non-Latin layout is active.** Repro (5/5 debug, 1/1 release): activate the Thai layout in W1, press hardware Ctrl+P, Ctrl+E or Ctrl+J: the page receives `key = "ย"`, `code = "KeyP"`, so no shortcut fires. Cause: `apps/desktop/src/tools/modbus-master/lib/shortcuts.ts:35` and `components/sidebar/PollList.tsx:155` compare `e.key.toLowerCase()`. The harness keys carry scan codes, so `code` is correct as with a real keyboard; matching on `e.code` (or both) is the usual fix. Outside the checklist: the PM decides.
**D9 (frontend, low) After a failed pop out, keyboard focus falls to BODY.** Repro (5/5, hooks build): arm the hook, click pop out; the sub-window stays but `document.activeElement` is `BODY`, not inside the sub-window. CHK2-F16 says "focus kept". Everything else in F16 passes.
**Checklist remarks (not product defects):** CHK2-F13 "after SetWindowPos to 1 x 1 the OS keeps the minimum" is not true: Win32 applies the minimum track size to user resizing only; the native window goes to 1 x 1 and so does the launcher (control run); the drag minimum is exact: suggest dropping the clause. CHK2-R7 (f) "Esc closes it": the first Esc closes the popup and the page stays blocked in menu mode; a second Esc ends menu mode (standard Windows behaviour, 2 presses, 5/5 runs). CHK2-D3: the simulator's own `fault delay 3` is quantized by the simulator process's 15.6 ms timer (the simulator does not hold the timer resolution), so 16 polls get one request every 15.6 ms and `effective` is 249 ms, not about 50 ms; the CHK criteria still hold. The shortest interval in D10 equals the limit exactly (zero margin, pass with >=).
