## 4. Failures and findings
1. **CHK2-F1/F2 (scroll): the first visible address is lost when a row is focused (frontend).** After pop out or dock with `focusAddress` in the handoff, scrollTop stays 0 (expected: address 2 first visible). Likely cause: the effect in `DataGrid.tsx` that scrolls the focused row into view overrides the restored `topAddress`. Repro: handoff `{"topAddress":2,"selection":[{"start":3,"end":5}],"anchorAddress":3,"focusAddress":5,...}`: only a selection gives 48 (OK), only a focus gives 0, focus at 20 gives 32.
2. **CHK2-E12 (boundary): the default sub-window shows the popover, not the dock (frontend + design clarification).** DES-002 2.3.3: width >= 640 -> dock; the default size is 640 x 368 but the PollView body measures 636 px (frame border), so a new poll gets the popover that covers the data card. 900 px gives the 300 px dock and 600 px the popover as specified.
3. **CHK2-E13 (fit): at the default 640 px with live data the status line overflows and clips controls (frontend).** The frame's right edge is x = 934, "Show Raw" ends at 941.5, the `⋯` menu (950-974) is clipped and unreachable (reachable offline, because the freshness chip is absent). DES-002 2.3.2 says the line hides the reason text, then `F` and `ID`, and never hides the controls; the container query hides `ID`/`F` only below 430 px. `StatusLine.tsx` was edited by the FE-003 agent during the round: re-verify after merge.
4. **CHK2-R1 (Tab order): sub-window DOM order is by poll id, not front first (design question Q-FE2-16).** DES-002 9 says "z-order from the front". The F6 region cycle passes.
5. **Performance (CHK2-Q1..Q3, browser smoke only), on a machine shared with Vitest runs:** Q1 8 tiled sub-windows at 100 ms for 60 s: Pause to the Paused chip 7-17 ms, 0 long tasks in counted runs (one informational run saw 3 tasks of 50-52 ms). Q2 4 sub-windows + 4 native windows for 30 s: 0 long tasks. Q3 drag (20 s) and resize (10 s) of one sub-window with 8 polls at 100 ms: 0 long tasks in 4 of 5 full runs and one 51 ms task in one run; the other 7 tables kept updating and their DOM mutation rate during the drag (~846/s) equals idle (~860/s) (proxy for "no extra renders"). The "0 long tasks over 50 ms" criterion sits at the threshold under shared CPU: re-run on a quiet machine and on WebView2 (Q4).
6. **Observations (checklist/design wording, not failures):** O-1 typing a connection marks the profile Modified, so the title is `Modbus Master - Untitled * - Connected (...)` (CHK2-C2 quotes it without `*`). O-2 S6 adds "A kept poll keeps polling in the background." for a poll with the run intent on even when it is Paused because "Start polling when connected" is off. O-3 snap tie: a moving edge 4 px from both B.left and B.left - 8 snaps to B.left. O-4 a pointer within 24 px of the tile-area border shows a zone and suspends edge snapping (as specified). O-5 a press raises a sub-window but the new z-order is reported to Rust at the next layout action (Save flushes first). O-6 Write... with the link down does nothing (matches DES-001). O-7 CHK2-B5 says a duplicate is "paused"; with auto start on and a connected link the fake starts it (consistent with the backend decision Q-BE2). O-8 the Disconnected announcement is assertive.

A render-count probe per PollView (dev only) to replace the DOM mutation proxy of Q3. 7. An announcement log in the fake window IPC (or `data-seq` on live regions).
