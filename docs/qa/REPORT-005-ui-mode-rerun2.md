## 5. Failure F1: CHK2-E26 sweeps at 125% scale (owner: frontend, or designer/PM if L is meant to be rounded)
At active frame 468 and 125%: L measured 464.8, `data-step` seen 4, design step 5 (counters keep `Err`: `Tx 1234 · Err 0 · SR 100 ms` instead of `Tx 1234 · SR 100 ms`). Scratch evidence (deleted): the same at every active frame T+3 at 125% where L = T - 0.2: frame 723 (L 719.8: step 0 seen, design 1), 813 (809.8: 0 vs 1), 623 (619.8: 1 vs 2), 609 (605.8: 2 vs 3), 503 (499.8: 3 vs 4), 468 (464.8: 4 vs 5). 150% is clean (L stays an integer for active frames). No control clips and the counters are never cut: the only effect is the step flipping 0.2 px late. Cause by code reading: `useElementWidth` in `apps/desktop/src/tools/modbus-master/components/poll-view/context.tsx` does `Math.round(latest)` of the fractional width (lines 73 and 84), so 464.8 becomes 465, which is not below 465. Repro: Chromium `--force-device-scale-factor=1.25`, viewport 1618 x 834, dev page `VITE_FAKE_IPC=manual`, one connected active sub-window with frame width 468 (`LAYOUT_SEED`), `freezePollCounters(id, {requests: 1234, errors: 0})`; read `data-step` on `poll-status-line`: 4, the line is 464.8 px wide. Decision needed: either L is the exact element width (stop rounding) or L is defined rounded (then DES-002 2.3.2 and E26 must say so).
