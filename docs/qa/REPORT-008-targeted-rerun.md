**1c. DEFECT D11 (frontend, medium-high): the toolbar flickers in a width band.** When the window rests at a client width of about 664-672 css px (outer 848-856 physical at 125 %), the label mode changes on every animation frame, indefinitely: seen at rest at outer 848, 850, 852, 854, 856: 165-167 mode changes in 2 s; the toolbar height flips 84.8 px (full) and 40.8 px (icon), so the whole PollView jumps. Outside the band 0 events in 2 s (outer 840, 846, 858, 860, and after drags). Real slow drag across the band (120 steps x 20 ms, 2 x narrowing and 2 x widening): 11 label-mode transitions per crossing instead of 1; height sequence 84.8, 40.8, 84.8, 40.8 ... (11 reversals); no document scrollbar frame seen; 17-19 frames per drag had a mode not matching the width. Root cause (read in the code, not changed): `useElementWidth` in `poll-view/context.tsx` line 92 takes `entry.contentRect.width` (content box without padding) while the initial read uses `getBoundingClientRect` (border box); the toolbar padding differs per mode: full is `px-4` (32 px), icon is `px-3` (24 px); so full asks for icon while the toolbar width is below 672 css, and icon asks for full while at 664 or more: between 664 and 672 each mode asks for the other. It also moves the real threshold from 640 to about 664-672 css, so 640-663 css is icon-only against the spec. Fix suggestion: measure the border box (`entry.borderBoxSize[0].inlineSize`), or put the padding on an inner element, or use the same padding in both modes; add hysteresis only if needed. Repro: pop out a poll; set the window outer width to 850 px at 125 % scale (client 665.6 css), connected and polling: the toolbar flickers between 41 px and 85 px high; or slowly drag the right edge through that width. Evidence: `d10-band.json`, `d10-drag-640.json`, `d10-threshold-scan.json`.
