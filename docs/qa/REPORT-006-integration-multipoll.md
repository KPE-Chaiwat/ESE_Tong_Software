## 3. Defects (real, with owner and repro)
**D1 (backend, medium) The scan rate is quantized to the Windows 15.6 ms timer tick.** One poll alone, request interval measured on the simulator log: configured 20 / 50 / 100 / 250 / 500 ms give mean intervals 31.2 / 62.4 / 109.1 / 260.4 / 508.6 ms (+56 % / +25 % / +9 % / +4.2 % / +1.7 %; min/max 30-33, 60-64, 107-112, 250-267, 500-517). 20 ms is shown as `SR 20 ms (effective 31 ms)`. With 1, 2, 4 and 7 polls at 100 ms the interval of poll 1 stays 109: it does not depend on the number of polls. 8 standard polls over 60 s: seven 100 ms polls 556 requests each (92 % of 605), mean 109, P8 (1000 ms) 60 requests mean 1009.6. CHK2-D2 (>= 80 %) still passes. Suspected cause: tokio sleep granularity on Windows (7 x 15.6 = 109.2); needs `timeBeginPeriod(1)` or a high-resolution timer.
**D2 (frontend with the Tauri/WebView2 host; needs investigation; high for keyboard users) CHK2-R7: one Alt tap puts the window into OS menu mode and freezes the page.** Repro (5/5): focus a W1, press and release Alt alone with hardware input, also after an Alt-drag (hold Alt, drag a sub-window, release). Then the page does not answer CDP (`page.evaluate` and `/json/list` time out after 3 s), a hardware Ctrl+P does not pause the poll (simulator requests unchanged), the next Alt tap or Esc recovers it. CHK2-R7 says focus must stay in W1 content. Not visible with Playwright's CDP keyboard (it never reaches the OS). Needs a preventDefault of the Alt keyup and/or handling WM_SYSKEYUP/SC_KEYMENU in the window layer.
**D3 (backend, low) Native window minimum outer width is 599 px = 479.2 logical at 125 %, expected 480 (600 px).** Height is exact (400 px = 320). Cause: the client minimum 465 x 1.25 = 581.25 is truncated to 581 (+ 18 frame = 599). Repro: real OS drag of a W2 right edge inward (5/5).
**D4 (frontend, low-medium) The first click on [Apply scale] is lost when the field blur shows an error message.** Repro (5/5): Apply a 4-20 mA scale, type Decimals `7`, one mouse click on [Apply scale]: the field message appears, the button moves, no header "Scale not applied. Fix the highlighted fields."; a second click shows it. Raw min `-1` works (the layout does not move). Typing, then Tab, then click works (CHK3-C7).
**D5 (backend, low) W1 is not clamped to the work area at creation.** The default W1 (1280 x 800 logical inner = 1294 x 837 outer) cascaded 24 px from the launcher at physical (254, 163) size 1618 x 1047: its bottom edge is at 1210 px on a 1080 px screen (work area ends at 1020). Native poll windows wrap/clamp (verified); W1 does not (small screens, 1536 x 864 logical).

## 4. Observations (not defects; owner in brackets)
- **O1 (design)** The default pop out gives a W2 of outer 640 x 368 logical (client about 626 px), below 640, so its setup is forced to the rail and cannot be opened until the window is widened (rail click: `data-presentation` stays `rail`). The draft (Quantity "200" with message) is there and visible after widening to 900.
- **O2 (design/frontend)** REV-006 M-1 timeline, real backend: click -> sub-window removed 204 ms (the pop out button showed the spinner state before), native window listed by the OS 679 ms, `data-ready` 705 ms: the poll is shown nowhere for about 0.48 s. Values are in the new window at once (grid live, no "Waiting for first response").
- **O3 (design, D-002-19)** In a real Timeout the counters carry `(effective N ms)` (the cycle is at least the timeout), so the reference content does not occur: at frame 640 (L 636.8) the counters `Tx 1409 · Err 3 · ID 1 · F 03 · SR 100 ms (effective 1580 ms)` need 457.4 px, get 342.1 (cut 115.3 px, documented last resort), and the reason text gets 0 px (it would need 144.8); the reason has 0 px at every frame 624-723. Controls never clip anywhere. Counters complete from frame 724 in Timeout, from 384 in Polling (designer estimate 393/400 conservative).
- **O4 (checklist)** Edge snap threshold in the product is 8 px (snaps at 4, 7, 8 px; not at 9, 10, 14); CHK2-I5 says within 7. Snap lines include the gap offsets `left + 8` and `right - 8` of other windows.
- **O5 (frontend)** After a page reload (CDP `Page.reload`; the hardware F5 does not reload the page, 0 reloads) polls, rectangles, states and values re-attach (E14 pass), but the profile's Modified flag is lost (`Untitled *` -> `Untitled`): unsaved polls no longer prompt at close.
- **O6 (backend)** Native placements are stored in whole logical px: a window at physical y 111 reopens at 110 after a restart (125 %; x, w, h exact).
- **O7** The "Save changes?" before loading a profile reads "Save this setup as a profile before closing?" (wording says closing).
- **O8 (hygiene)** The app writes `%APPDATA%\com.esefact.desktop\.window-state.json` on graceful exit (outside the data dir). QA deleted it at the end.
- Pointer: at 125 % one CSS px is 1.25 device px, so exact frame widths need the keyboard (`Ctrl+Alt+Shift+Arrow`, 1 px) after the mouse drag.

## 6. Test defects and diagnosis
**CHK2-G5 (counted runs 2/2 fail, alone 2/5 fail):** the last assertion read `desktop.w2Pages()` the instant after the OS windows were gone; Playwright removes the page objects of destroyed webviews 1-106 ms later. Test timing defect: the assertion now polls the page list; 6/6 pass alone afterwards. No app defect (OS window list 0, TCP table 0, simulator `CLOSE` logged, app process exit code 0, no WebView2 process of the run left). Earlier harness lessons (not product): a tight loop of synchronous `execFileSync` blocks the Playwright event loop; fractional CSS px cannot be hit at 125 % by the pointer; a CDP busy-loop is not reported as a long task; parallel workers break hardware input (the first 4-worker run had interference failures and was discarded; one worker now).
