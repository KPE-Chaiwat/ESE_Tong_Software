# BE-006 Combined-register interpretation persistence

Revision 1, 2026-10-18. Upstream REQ/DES/FE-006 revision 1; coordinated with BE-005. Contract only, no implementation/verification claimed. D-006-02 in questions.md is the shared schema decision.

## DTO and command contract

Extend existing ValueFormat rather than introduce a conflicting second format: keep JSON `unsigned`, `signed`, `hex`, `binary` exactly; append `signed32`, `unsigned32`, `float32`, `signed64`, `unsigned64`, `float64`. Extend DisplaySettings with REQUIRED boolean `swapBytes` and `reverseWords` in current-schema/IPC data. Existing `format`, `addressBase`, `showAlias`, `copyAlias` remain. Default format unsigned, both swaps false. The frontend draft's `type` maps to display.format; do not serialize a second interpretation field. Swaps remain saved/retained but ignored for bits and 16-bit formats.

Existing `mm_set_poll_view({pollId, view:{display,...}})` remains the command; display is a complete DisplaySettings object, not a nested patch. No new commands or sample-value DTOs. PollViewSettings adds optional colorRules through BE-005. Validate the complete prospective config (old config + supplied patch), including disabled rules, before changing ANY field. Changing display and rules together is permitted. Same validation is mandatory for PollConfigInput, profile save/read/apply, and duplicate staging. Identical valid applied patch is a no-op. Existing PollConfigChanged and PollListChanged carry acknowledged config; return null only after commit. Reject retains previous applied configuration, values and all persisted settings; no wire operation, poll-state transition, counter reset or scheduler restart for display edits.

Error envelope existing AppError {code,message,field}. Invalid format/boolean/shape: validation, field display, `Choose a supported interpretation and byte/word order.` Wrong address base retains existing validator. For incompatible Raw/Displayed rule threshold in integer64 mode: validation, field colorRules, `Interpretation not applied. Rule "{name}" requires whole-number thresholds for 64-bit integers.` Syntax, magnitude and Between validation follow BE-005; magnitude errors retain their specific threshold text. Deserialization failures must map to this validation envelope, not an opaque invoke parse string. Unknown enum never silently defaults. FC01/02 may store any valid register setting and rules compatible with the stored format; function switching must not reveal an invalid dormant rule set.

## Shared profile schema 3

This round writes ONE schema version 3 containing both features 005 and 006. PollProfile adds required colorRules array; display adds required swapBytes/reverseWords and expanded format enum. No rule matches, group values, BigInts, selection or drafts in profiles. No package/app version change is implied. Set PROFILE_SCHEMA_VERSION=3 only during implementation, through normal source editing (product version remains pnpm version:set only).

Read schema 1 via existing legacy migration then upgrade; read schema 2 through an explicit legacy DTO (do not broaden its enum). Preserve original format, addressBase, alias/copy settings, aliases, scale/overrides/valueColumns, active/run intent, hosts/order/layout and all other existing semantics. Add swaps=false and colorRules=[] to every migrated poll. v1 keeps its existing migration defaults; do not invent an unsigned override when signed/hex/binary exists. There is no separate legacy interpretation field to migrate: display.format is authoritative. Missing/malformed/unknown legacy format is invalidProfile under the existing required-field contract. Unsigned is the default for new settings, not a repair for a damaged old profile. Runtime current-schema and IPC require the new fields: no blanket serde defaults that hide malformed v3. v2 files containing new enum strings are invalidProfile, not a backdoor current schema.

profiles_get returns schemaVersion=3 and migratedFrom=original 1 or 2, does not rewrite files, and migration does not mark Modified. Explicit profiles_save writes only schema3 atomically (same-directory temp/rename); migratedFrom remains metadata excluded from disk. mm_apply_profile validates the entire current-schema config before stopping/replacing any session or closing any window. profiles_save rejects unsupported incoming schema rather than reinterpreting a newer object as v3. profiles_list marks bad/newer entries readable=false while retaining others. Schema >3 -> unsupportedSchema; malformed schema3, missing required fields, unknown enum, wrong boolean or incompatible rule -> invalidProfile. Missing/noninteger/negative schema is invalidProfile. Existing profile filename/name safety, limits, atomic-write recovery and permissive disconnected setup-draft validation remain intact; no new requirement to be runnable on the current link.

## Samples and interpretation ownership

FE uses only a complete current-definition snapshot; definition edits already clear stale samples. Display changes can reinterpret the retained snapshot. No word from failed/previous responses or another definition may fill a group. Verify that existing generation/seq behavior prevents an in-flight old-definition reply from repopulating cleared data; fix only if a concrete gap is found. FE-006 owns grouping, BigInt and IEEE display. Never JSON-serialize sampled BigInt in profile or opaque UI handoff; handoff contains drafts/addresses/settings only. DisplaySettings is relayed unchanged across native/workspace attachment and duplicate/export/import. Combined mode preserves scales and columns while frontend derives their unavailable effective state; raw FC06/16 commands remain unchanged.
